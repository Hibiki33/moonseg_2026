## 接入前最值得记住的事实

1. **没有一组可以原样作为当前五类标签直接拼接。** LunarSeg 合并了非障碍背景；DFKI 只标实例；POLAR 把阴影单独成类；Chang’e-3/Apollo 缺分割真值。
2. **LunarSeg 论文数量有内部矛盾。** 总数和 train/val/test 合计为 5,143，但四场景分项合计 4,876；尚未完整解包查清差额。
3. **LuMon 掩码存在文档/代码用途冲突。** 数据卡描述为深度有效区，而评测脚本把指定掩码目录当作暗区缓存，不能直接默认同义。
4. **DFKI 两包不是相同样本的简单格式转换。** YOLO 训练图数量是 COCO 的三倍；源编号跨 split 重复，尚需核查是同源派生还是命名碰撞。
5. **POLAR-Sim 的显示灰度不是类别号。** 转换脚本输出 0/86/128/43；框类别 ID 又与分割 ID 不同。检测目录的 3,985 个文本还包含 12 个 `classes.txt`。
6. **Apollo 同一曝光有多个扫描和拼接版本。** 以任务/胶卷/帧号和派生关系去重；已处理天空、接缝或色彩的图像不等于原始扫描。

每条的原始来源和复核范围均在对应专题中。原始 Grok 文本保留作调查记录；整理版已纠正上述可确认问题，并将未经像素验证的推断标明。

## 后续准备顺序

建议先取 **DFKI 的 COCO 包**做格式与重复编号检查，再取 **LuMon Chang’e-3**建立真实月面样例表；随后准备 **LunarSeg** 的完整计数与标签检查。需要研究长阴影时，先取 **POLAR 一个地形及对应分割标签**，再决定是否取全包、网格或视频。**Apollo** 先建帧目录和筛选规则，取得一批经确认的原始帧版本后再标注。

这个顺序基于下载成本、现成标签和人工整理成本，未做性能排名。各专题给出可手工执行的入口、需要登录或受访问限制的环节，以及尚未取得的内容；没有把 HEAD/Range 成功写成数据已下载。

机器可读入口登记见 [sources.json](sources.json)。其中 `bulk_downloaded=false` 表示数据本体尚未批量取得；`competition_training_allowed=false` 保留本次比赛的数据范围约束。这个 JSON 是调研登记文件，没有被训练数据加载器引用。

建议后续下载时保留源 URL、版本/DOI、文件名、远端字节数、原始样本标识、场景分组、标签 schema、许可来源和下载状态。检查字节数、归档结构、实际图像/标签格式及配对关系即可；本次未新增训练代码、测试文件或内容校验流程。
